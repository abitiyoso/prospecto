## Phase 4 — commercial foundation and event reporting verified

User authorized the next bounded milestone. No customer receives a subscription, credits, invoice or paid status on signup. No merchant account/key has been supplied, so live checkout/cancellation and payment verification remain unavailable. This milestone is not a live payment integration.

Elenio migration local 20261105004019_commercial_reporting.sql corresponds to hosted MCP migration 20261105005053. Adds 11 RLS-protected tables: commercial_catalog, credit_action_rates, subscriptions, payment_receipts, payment_event_keys, invoices, credit_buckets, credit_reservations, credit_allocations, credit_ledger and outbound_events. Catalogs are authenticated-read/server-write; tenant financial/event records are tenant-read/trusted-write; payment receipts/events/invoices are owner/admin-read. All public financial mutations are SECURITY INVOKER and executable only by service_role. No service-role credential was added to the application.

The trusted normalized settlement boundary checks catalog/amount/effective date/paid cycle, idempotently records provider event and payment IDs, prevents repeated/old/overlapping cycles, creates paid invoice/grant once and resets monthly credits without rollover. It deliberately cannot verify an actual merchant signature itself: a merchant adapter must validate signature, merchant/order/IDR amount and authoritative settlement before calling it. Immutable paid price/rate versions require new IDs for changes. Ledger/provider events are append-only for application roles.

Credit reservation uses per-workspace advisory transaction locks and idempotent job keys. It reserves against enabled server rates, uses monthly credits before top-ups ordered by expiry, settles only successful units, releases failed/zero-result units and supports idempotent job refunds. Expired buckets never regain spendable balance from late release/refund. Product/lead/seat/active-campaign capacity enforcement is separate from wallet balance; top-ups cannot bypass it. Existing free manual workflows are preserved when no paid entitlement exists. Scheduled billing/cancellation/reconciliation and monetary provider refunds are still dependent on a real adapter/worker; no money was moved.

Subscription & Credits now loads proposal pricing, actual balance/reservations, capacities, bucket expiry, up to 50 ledger entries/invoices, and subscription state/period from the backend. Sidebar shows plan/balance/period, no pricing. Workspace timezone is owner/admin configurable among Jakarta/Makassar/Jayapura. UI never claims payment success. Checkout/change/cancel commands return 409; unconfigured webhook returns 503 without parsing or granting from an unverified payload. lib/payment-adapter.ts defines the future provider boundary but has no configured implementation.

Analytics uses aggregate RPCs, validated date/campaign filters and workspace-local inclusive days with an exclusive end. Metrics count unique contacts per campaign in the selected sent cohort; subsequent events must also occur in the range. Open/reply ratios expose numerator/denominator and show — when sent=0. Only trusted persisted outbound_events can affect outreach metrics. The separate research count uses still-retained research_runs, not a billable ledger, and explicitly excludes deleted product history. Current research rates are unpriced; existing Firecrawl calls do not debit credits. If a priced rate is enabled before a credit worker is connected, the research API fails closed before provider access.
